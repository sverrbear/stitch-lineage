# v0.5.0 — review Metabase repairs in the browser

After a dbt column rename, Stitch can now show the affected Metabase reports, explain the
proposed calculation and dashboard filter changes, and apply them after explicit approval
in the local app. The same Mend engine powers the CLI and browser.

- **Browser Mend:** compare the last two local builds, declare replacement columns, review
  query and dashboard changes, approve once, and inspect per-report results and recovery data.
  Previews expire after 15 minutes; changed inputs require another review.
- **Readable repairs:** calculations, filters, and dashboard mappings show field names and
  before/after values. Exact query JSON remains available for inspection and recovery.
- **Conservative defaults:** omitted `mend.auto` now enables only declared rename repoints.
  Strip and archive require explicit policy opt-in. The browser also requires a separate
  choice for each review. Apply checks the current policy and collection restrictions.
- **Qualified search:** `model.column` searches put exact column matches ahead of fuzzy
  suggestions while keeping display-prefix aliases searchable.
- **Dependency updates:** patched Python dependencies and frontend build tooling; Node
  24.22.1 is the development/build runtime. Installed Stitch still ships a prebuilt browser app
  and needs no Node installation.

## Upgrade

```sh
pip install --upgrade stitch-lineage
```

An omitted `mend.auto` becomes `[repoint]`. **Existing explicit lists are preserved**, including
`[repoint, strip, archive]` and `[]`. To adopt the conservative policy in an existing project:

```yaml
mend:
  auto: [repoint]
```

Refresh dbt artifacts, sync Metabase, and run `stitch build` after the schema change. Mend uses
`.stitch/graph.prev.json` and `.stitch/graph.json`; a first build establishes the baseline.
Open `stitch serve` and choose **Mend**. Inspect a report after repair: query execution does
not establish that its business meaning or numbers are correct.

Native SQL and protected, unreadable, or unsupported reports remain manual. Card and dashboard
writes are not transactional. Query failures trigger rollback attempts, which can fail;
dashboard failures may leave partial updates. Save recovery data before another completed
apply or server restart replaces it. Static exports remain read-only.
